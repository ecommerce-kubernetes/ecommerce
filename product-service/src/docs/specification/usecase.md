# [상품 애플리케이션 서비스] 유스케이스 명세서

> 본 문서는 상품 서비스의 기능적 요구사항을 정의하고, 각 기능별 비지니스 흐름(정상, 대안, 예외 흐름)의 기준을 제공한다. (현재는 카테고리 관련 유스케이스만 작성되어 있다.)

## 1. 개요 (Overview)

- **도메인**: 카테고리 조회(최상위/하위/상세/트리), 카테고리 관리(생성/수정/이동/삭제)
- **주요 행위자**: 비인가 사용자, 인가된 사용자, 인가된 관리자(`ROLE_ADMIN`)

## 3. 유스케이스 상세 명세 (UseCase Specifications)

### 3.1. [UC-CAT-01] 최상위 카테고리 목록 조회

1. 기본 정보
    - 목적: 네비게이션 진입점이 되는 최상위 카테고리 목록을 조회한다.
    - 행위자: 비인가 사용자, 인가된 사용자
    - 사후 조건: 데이터 상태 변경 없음(Read-only).

2. 기본 흐름
    1. [행위자]: 최상위 카테고리 목록 조회를 요청한다.
    2. [시스템]: 부모가 없는(최상위) 카테고리 목록을 조회한다.
    3. [시스템]: 각 카테고리의 식별자, 이름, 이미지 경로, 리프 여부(`isLeaf`)를 반환한다.

3. 대안 흐름 / 예외 흐름
   (해당 없음)

### 3.2. [UC-CAT-02] 하위 카테고리 목록 조회

1. 기본 정보
    - 목적: 특정 카테고리 바로 아래의 하위 카테고리 목록을 조회한다(드릴다운 탐색).
    - 행위자: 비인가 사용자, 인가된 사용자
    - 사후 조건: 데이터 상태 변경 없음(Read-only).

2. 기본 흐름
    1. [행위자]: 상위 카테고리 식별자를 포함하여 하위 카테고리 목록 조회를 요청한다.
    2. [시스템]: 요청받은 식별자의 카테고리를 조회한다.
    3. [시스템]: 해당 카테고리의 자식 카테고리 목록을 조회한다.
    4. [시스템]: 각 자식 카테고리의 식별자, 이름, 이미지 경로, 리프 여부(`isLeaf`)를 반환한다.

3. 대안 흐름
    - [A-1] 자식 카테고리가 없는 경우 (기본 흐름 3번에서 분기)
        1. [시스템]: 빈 목록을 반환한다.

4. 예외 흐름
    - [E-1] 카테고리 없음 (기본 흐름 2번에서 발생)
        1. [시스템]: 요청받은 식별자의 카테고리가 없음을 확인한다.
        2. [시스템]: 예외(`CATEGORY_NOT_FOUND`)를 반환하고 흐름을 종료한다.

### 3.3. [UC-CAT-03] 카테고리 상세 조회

1. 기본 정보
    - 목적: 특정 카테고리의 상세 정보와 루트부터 자신까지의 경로(브레드크럼)를 조회한다.
    - 행위자: 비인가 사용자, 인가된 사용자
    - 사후 조건: 데이터 상태 변경 없음(Read-only).

2. 기본 흐름
    1. [행위자]: 조회할 카테고리 식별자를 포함하여 상세 조회를 요청한다.
    2. [시스템]: 요청받은 식별자의 카테고리를 조회한다.
    3. [시스템]: 카테고리의 `path`를 기반으로 루트부터 자신까지의 조상 카테고리 목록(브레드크럼)을 조회한다.
    4. [시스템]: 식별자, 이름, depth, 리프 여부(`isLeaf`), 브레드크럼을 반환한다.

3. 대안 흐름
    - [A-1] 최상위 카테고리인 경우 (기본 흐름 3번에서 분기)
        1. [시스템]: 브레드크럼은 자기 자신 하나만 포함한다.

4. 예외 흐름
    - [E-1] 카테고리 없음 (기본 흐름 2번에서 발생)
        1. [시스템]: 요청받은 식별자의 카테고리가 없음을 확인한다.
        2. [시스템]: 예외(`CATEGORY_NOT_FOUND`)를 반환하고 흐름을 종료한다.

### 3.4. [UC-CAT-04] 카테고리 트리 조회

1. 기본 정보
    - 목적: 전체 카테고리를 최상위부터 하위까지 트리 구조로 조회한다(네비게이션 메뉴 구성용, 캐싱을 전제로 한다).
    - 행위자: 비인가 사용자, 인가된 사용자
    - 사후 조건: 데이터 상태 변경 없음(Read-only).

2. 기본 흐름
    1. [행위자]: 전체 카테고리 트리 조회를 요청한다.
    2. [시스템]: depth 오름차순으로 전체 카테고리를 조회한다.
    3. [시스템]: 각 카테고리를 부모-자식 관계에 따라 재귀적인 트리 구조로 조립한다.
    4. [시스템]: 최상위 카테고리를 기준으로 각 노드의 식별자, 이름, depth, 리프 여부(`isLeaf`), 자식 목록을 반환한다.

3. 대안 흐름 / 예외 흐름
   (해당 없음)

### 3.5. [UC-CAT-05] 카테고리 생성

1. 기본 정보
    - 목적: 최상위 또는 특정 카테고리 하위에 새 카테고리를 생성한다.
    - 행위자: 인가된 관리자
    - 사후 조건: 새 카테고리가 생성되어 저장된다.

2. 기본 흐름
    1. [행위자]: 카테고리 이름, 이미지 경로, 부모 카테고리 식별자(선택)를 포함하여 생성을 요청한다.
    2. [시스템]: 부모 카테고리 식별자가 없으면 최상위 카테고리 생성 흐름으로 진행한다.
    3. [시스템]: 같은 계층(형제)에 동일한 이름의 카테고리가 있는지 확인한다.
    4. [시스템]: 식별자를 발급하고 카테고리를 생성한다.
    5. [시스템]: 생성된 카테고리를 저장하고 식별자를 반환한다.

3. 대안 흐름
    - [A-1] 부모 카테고리 식별자가 있는 경우 (기본 흐름 2번에서 분기)
        1. [시스템]: 부모 카테고리를 조회한다.
        2. [시스템]: 부모 카테고리에 상품이 등록되어 있는지 확인한다.
        3. [시스템]: 기본 흐름 3번으로 진행하여 부모 식별자를 기준으로 형제 이름 중복을 확인한다.
        4. [시스템]: 부모의 depth + 1을 depth로, 부모의 path에 새 식별자를 이어붙인 값을 path로 하여 카테고리를 생성한다.

4. 예외 흐름
    - [E-1] 부모 카테고리 없음 (대안 흐름 A-1 1번에서 발생)
        1. [시스템]: 요청받은 부모 식별자의 카테고리가 없음을 확인한다.
        2. [시스템]: 예외(`CATEGORY_NOT_FOUND`)를 반환하고 흐름을 종료한다.
    - [E-2] 부모 카테고리에 상품 존재 (대안 흐름 A-1 2번에서 발생)
        1. [시스템]: 부모 카테고리에 등록된 상품이 있음을 확인한다.
        2. [시스템]: 예외(`PARENT_CATEGORY_HAS_PRODUCT`)를 반환하고 흐름을 종료한다.
    - [E-3] 형제 이름 중복 (기본 흐름 3번에서 발생)
        1. [시스템]: 같은 계층에 동일한 이름의 카테고리가 이미 존재함을 확인한다.
        2. [시스템]: 예외(`DUPLICATE_SIBLING_CATEGORY_NAME`)를 반환하고 흐름을 종료한다.
    - [E-4] 최대 깊이 초과 (기본 흐름 4번에서 발생)
        1. [시스템]: 부모 카테고리의 depth가 최대(5)임을 확인한다.
        2. [시스템]: 예외(`EXCEED_MAX_DEPTH`)를 반환하고 흐름을 종료한다.

### 3.6. [UC-CAT-06] 카테고리 수정

1. 기본 정보
    - 목적: 카테고리의 이름과 이미지 경로를 수정한다.
    - 행위자: 인가된 관리자
    - 사후 조건: 카테고리의 이름/이미지 경로가 변경된다.

2. 기본 흐름
    1. [행위자]: 수정할 카테고리 식별자와 변경할 이름, 이미지 경로를 포함하여 수정을 요청한다.
    2. [시스템]: 요청받은 식별자의 카테고리를 조회한다.
    3. [시스템]: 이름이 기존과 동일하면 중복 검증 없이 바로 수정한다.
    4. [시스템]: 카테고리의 이름과 이미지 경로를 수정하고 식별자를 반환한다.

3. 대안 흐름
    - [A-1] 이름이 변경되는 경우 (기본 흐름 3번에서 분기)
        1. [시스템]: 같은 계층(형제, 자기 자신 제외)에 동일한 이름의 카테고리가 있는지 확인한다.
        2. [시스템]: 기본 흐름 4번으로 진행한다.

4. 예외 흐름
    - [E-1] 카테고리 없음 (기본 흐름 2번에서 발생)
        1. [시스템]: 요청받은 식별자의 카테고리가 없음을 확인한다.
        2. [시스템]: 예외(`CATEGORY_NOT_FOUND`)를 반환하고 흐름을 종료한다.
    - [E-2] 형제 이름 중복 (대안 흐름 A-1 1번에서 발생)
        1. [시스템]: 같은 계층에 동일한 이름의 카테고리가 이미 존재함을 확인한다.
        2. [시스템]: 예외(`DUPLICATE_SIBLING_CATEGORY_NAME`)를 반환하고 흐름을 종료한다.

### 3.7. [UC-CAT-07] 카테고리 이동

1. 기본 정보
    - 목적: 카테고리의 부모를 변경하고, 이동에 따라 하위 카테고리의 경로도 함께 갱신한다.
    - 행위자: 인가된 관리자
    - 사후 조건: 카테고리와 그 모든 하위 카테고리의 depth·path가 새 위치를 기준으로 갱신된다.

2. 기본 흐름
    1. [행위자]: 이동할 카테고리 식별자와 새 부모 카테고리 식별자(최상위로 이동 시 생략 가능)를 포함하여 이동을 요청한다.
    2. [시스템]: 이동할 카테고리를 조회한다.
    3. [시스템]: 새 부모 카테고리 식별자가 있으면 새 부모 카테고리를 조회한다.
    4. [시스템]: 새 위치(새 부모 기준 형제 관계)에 동일한 이름의 카테고리가 있는지 확인한다.
    5. [시스템]: 새 부모에 상품이 등록되어 있는지 확인한다.
    6. [시스템]: 이동 전 경로와 depth를 보관한 뒤, 카테고리를 자기 자신/하위 카테고리로 이동하려는 것은 아닌지, 새 부모의 depth가 최대인지 검증하고 카테고리의 depth와 path를 새 부모
       기준으로 갱신한다.
    7. [시스템]: 이동 전 경로로 시작하는 모든 하위 카테고리를 조회하여, 각 하위 카테고리의 경로 접두사와 depth를 새 위치 기준으로 함께 갱신한다.
    8. [시스템]: 이동된 카테고리의 식별자를 반환한다.

3. 대안 흐름
    - [A-1] 새 부모 식별자가 없는 경우(최상위로 이동) (기본 흐름 3, 5번에서 분기)
        1. [시스템]: 새 부모 조회와 상품 등록 여부 확인을 생략한다.
        2. [시스템]: 기본 흐름 6번에서 depth는 1, path는 자신의 식별자로 갱신한다.
    - [A-2] 이동 전후 depth와 path에 변화가 없는 경우 (기본 흐름 7번에서 분기)
        1. [시스템]: 하위 카테고리 조회 및 갱신을 생략한다.

4. 예외 흐름
    - [E-1] 이동할 카테고리 없음 (기본 흐름 2번에서 발생)
        1. [시스템]: 요청받은 식별자의 카테고리가 없음을 확인한다.
        2. [시스템]: 예외(`CATEGORY_NOT_FOUND`)를 반환하고 흐름을 종료한다.
    - [E-2] 새 부모 카테고리 없음 (기본 흐름 3번에서 발생)
        1. [시스템]: 요청받은 새 부모 식별자의 카테고리가 없음을 확인한다.
        2. [시스템]: 예외(`CATEGORY_NOT_FOUND`)를 반환하고 흐름을 종료한다.
    - [E-3] 이동 위치에 형제 이름 중복 (기본 흐름 4번에서 발생)
        1. [시스템]: 새 위치에 동일한 이름의 카테고리가 이미 존재함을 확인한다.
        2. [시스템]: 예외(`DUPLICATE_SIBLING_CATEGORY_NAME`)를 반환하고 흐름을 종료한다.
    - [E-4] 새 부모에 상품 존재 (기본 흐름 5번에서 발생)
        1. [시스템]: 새 부모 카테고리에 등록된 상품이 있음을 확인한다.
        2. [시스템]: 예외(`PARENT_CATEGORY_HAS_PRODUCT`)를 반환하고 흐름을 종료한다.
    - [E-5] 자기 자신을 부모로 지정 (기본 흐름 6번에서 발생)
