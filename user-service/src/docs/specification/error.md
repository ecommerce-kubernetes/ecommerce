# [유저 애플리케이션 서비스] 에러 명세서

> 본 문서는 유저 서비스 REST API가 반환하는 에러 응답의 상태 코드, 에러 코드, 메시지를 정의한다. 클라이언트는 `code` 값을 기준으로 분기 처리하는 것을 권장하며, `message`는 사용자에게
> 그대로 노출 가능한 문구이다.

## 1. 공통 응답 형식

에러 발생 시 아래 형식의 JSON을 HTTP 상태 코드와 함께 반환한다.

```json
{
  "code": "USER_NOT_FOUND",
  "message": "해당 유저를 찾을 수 없습니다",
  "errors": [],
  "timestamp": "2026-09-03 12:00:00",
  "path": "/users/123"
}
```

| 필드          | 설명                                                          |
|-------------|-------------------------------------------------------------|
| `code`      | 에러를 식별하는 코드. 클라이언트 분기 처리의 기준이 되는 값                          |
| `message`   | 사용자에게 노출 가능한 에러 메시지                                         |
| `errors`    | 요청 값 검증(Validation) 실패 시에만 포함되는 필드별 상세 사유 목록. 그 외의 경우 생략된다. |
| `timestamp` | 에러 발생 시각 (`Asia/Seoul`, `yyyy-MM-dd HH:mm:ss`)              |
| `path`      | 에러가 발생한 요청 경로                                               |

검증 실패(`errors` 포함) 응답 예시:

```json
{
  "code": "INVALID_INPUT_VALUE",
  "message": "입력값이 올바르지 않습니다.",
  "errors": [
    {
      "field": "email",
      "reason": "이메일 형식이 올바르지 않습니다"
    },
    {
      "field": "password",
      "reason": "비밀번호는 영문, 숫자, 특수문자를 포함한 8자 이상이어야 합니다"
    }
  ],
  "timestamp": "2026-09-03 12:00:00",
  "path": "/users"
}
```

## 2. 에러 분류(Category)와 상태 코드 대응

에러 코드는 내부적으로 하나의 분류(Category)에 속하며, 분류에 따라 HTTP 상태 코드가 고정적으로 결정된다.

| 분류(Category)       | HTTP 상태 코드 | 의미                       |
|--------------------|------------|--------------------------|
| INVALID_REQUEST    | 400        | 요청 값 자체가 유효하지 않음         |
| UNAUTHORIZED       | 401        | 인증되지 않았거나 인증 정보가 유효하지 않음 |
| FORBIDDEN          | 403        | 인증은 되었으나 해당 작업에 대한 권한 없음 |
| NOT_FOUND          | 404        | 요청한 리소스가 존재하지 않음         |
| BUSINESS_CONFLICT  | 409        | 현재 상태와 충돌하는 비즈니스 규칙 위반   |
| SYSTEM_ERROR       | 500        | 서버 내부 시스템 오류             |
| EXTERNAL_API_ERROR | 503        | 외부 시스템 연동 실패/지연          |

## 3. 공통 에러

모든 API에 공통적으로 발생할 수 있는 에러이다.

| 상태 코드 | 에러 코드               | 메시지                 | 발생 상황                                                  |
|-------|---------------------|---------------------|--------------------------------------------------------|
| 400   | INVALID_INPUT_VALUE | 입력값이 올바르지 않습니다.     | 요청 바디/파라미터/쿠키의 `@Valid` 검증 실패 (필드별 사유는 `errors`에 포함)   |
| 401   | UNAUTHORIZED        | 인증이 필요한 접근입니다       | `X-User-Id`/`X-User-Role` 인증 헤더 없이 인가가 필요한 API에 접근한 경우 |
| 401   | UNAUTHORIZED        | 인증 헤더 형식이 올바르지 않습니다 | `X-User-Id`/`X-User-Role` 헤더 값이 파싱 불가능한 형식인 경우         |
| 403   | FORBIDDEN           | 접근 권한이 없습니다.        | 인증은 되었으나 요청한 리소스에 대한 권한이 없는 경우                         |

> 이 서비스는 API 게이트웨이가 선행 인증을 마친 뒤 `X-User-Id`/`X-User-Role` 헤더로 사용자 신원을 전달받는 구조이며(`HeaderPreAuthenticationFilter`),
> 401/403은 이 헤더 검증 단계 또는 권한 검증 단계에서 발생한다. 아래 도메인별 에러 목록과는 별개로 모든 API에 선행하여 적용될 수 있다.

## 4. 인증 (Auth) — `/auth/**`

| 상태 코드 | 에러 코드                     | 메시지                | 발생 상황                                                   |
|-------|---------------------------|--------------------|---------------------------------------------------------|
| 404   | USER_NOT_FOUND            | 해당 유저를 찾을 수 없습니다   | 로그인 시 입력한 이메일의 계정이 존재하지 않는 경우                           |
| 409   | PASSWORD_NOT_MATCH        | 비밀번호가 일치하지 않습니다    | 로그인 시 비밀번호가 저장된 값과 일치하지 않는 경우                           |
| 404   | REFRESH_TOKEN_NOT_FOUND   | 토큰이 존재하지 않습니다      | 토큰 재발급 시 저장소(Redis)에 해당 유저의 리프레시 토큰이 없는 경우(만료·로그아웃 등)   |
| 401   | REFRESH_TOKEN_EXPIRED     | 리프레시 토큰이 만료되었습니다   | 제시한 리프레시 토큰의 유효기간이 지난 경우                                |
| 401   | REFRESH_TOKEN_INVALID     | 유효하지 않은 토큰입니다      | 리프레시 토큰의 서명이 올바르지 않거나 형식이 손상된 경우                        |
| 403   | REFRESH_TOKEN_NOT_MATCHES | 리프레시 토큰이 동일하지 않습니다 | 제시한 리프레시 토큰이 저장된 토큰과 일치하지 않는 경우(탈취 의심 — 저장된 토큰은 즉시 폐기됨) |

## 5. 회원 (User) — `/users/**`

| 상태 코드 | 에러 코드                      | 메시지              | 발생 상황                                    |
|-------|----------------------------|------------------|------------------------------------------|
| 404   | USER_NOT_FOUND             | 해당 유저를 찾을 수 없습니다 | 배송지 추가/삭제 등 요청자 식별자의 유저가 존재하지 않는 경우      |
| 409   | EMAIL_ALREADY_EXISTS       | 이미 가입된 이메일입니다    | 회원가입 시 이미 사용 중인 이메일로 요청한 경우              |
| 404   | SHIPPING_ADDRESS_NOT_FOUND | 배송지를 찾을 수 없습니다   | 삭제하려는 배송지 식별자가 해당 유저 소유가 아니거나 존재하지 않는 경우 |
| 409   | INSUFFICIENT_POINTS        | 포인트가 부족합니다       | 보유 포인트보다 많은 금액을 차감하려는 경우                 |

## 6. 내부 API (Internal) — `/internal/users/**`

| 상태 코드 | 에러 코드          | 메시지              | 발생 상황                    |
|-------|----------------|------------------|--------------------------|
| 404   | USER_NOT_FOUND | 해당 유저를 찾을 수 없습니다 | 조회하려는 유저 식별자가 존재하지 않는 경우 |

## 7. 내부 처리 전용 에러

| 에러 코드                         | 메시지                                    | 발생 상황                                                                               |
|-------------------------------|----------------------------------------|-------------------------------------------------------------------------------------|
| SYSTEM_RETRY_EXHAUSTED        | 재시도 횟수를 초과하여 처리에 실패했습니다                | 포인트 사가 커맨드 처리 중 일시적 시스템 오류가 반복되어 최대 재시도(3회) 후에도 실패한 경우                              |
| SYSTEM_ERROR (직렬화 실패)         | 데이터 직렬화/역직렬화 중 시스템 오류가 발생했습니다          | 사가 응답 메시지를 아웃박스에 저장하기 위한 JSON 직렬화에 실패한 경우                                           |
| SYSTEM_ERROR (역직렬화 실패)        | 메시지 역직렬화에 실패했습니다.                      | 아웃박스 메시지 발행 시 저장된 헤더 JSON을 역직렬화하지 못한 경우                                             |
| SYSTEM_ERROR (인증 포트 오류)       | 유저 포트 에러                               | 인증(Auth) 서비스가 내부적으로 유저 조회/인증 포트를 호출했다가 예상치 못한 오류를 만난 경우                             |
| INVALID_CREDENTIALS           | 아이디 또는 비밀번호를 확인해주세요.                   | 인증 포트에서 `USER_NOT_FOUND`/`PASSWORD_NOT_MATCH`를 이 코드로 변환하여 인증 도메인 밖으로는 회원 존재 여부를 숨긴다 |
| OUTBOX_NOT_FOUND              | 아웃박스를 찾을 수 없습니다                        | 존재하지 않는 아웃박스 식별자로 상태 변경을 시도한 경우 (내부 로직 오류 상황)                                       |
| INVALID_OUTBOX_MESSAGE_STATUS | PENDING 상태의 아웃박스 메시지만 SENT로 변경할 수 있습니다 | 이미 발행 완료(SENT) 처리된 메시지를 다시 발행 완료로 전이시키려는 경우(동시 발행 경쟁 등)                             |
