# ADR-0009: 결제 완료 및 SAGA 트랜잭션 트리거 시점 정책

- **Status:** Accepted
- **Date:** 2026-06-17
- **Author:** 최민식
- **Tags:** #SAGA, #Payment
-

## 1. Context (배경 및 문제 상황)

현재 서비스는 주문에 관련된 자원(재고, 쿠폰, 포인트 등)을 차감하기 위해 Kafka를 이용한 SAGA 패턴을 사용하여 주문을 처리한다
이때 유저의 결제 흐름중 어느 시점에 내부 자원을 차감하는 SAGA 트랜잭션을 시작할지 결정이 필요하였고 3가지 대안을 고려하였다

## 2. Alternatives (고려했던 대안들)

1. **[대안 1: 주문 생성시 자원 차감]**
    - 설명: `POST /orders`를 통해 `PENDING Order`가 생성된 이후 SAGA 트리거를 실행해 주문 자원을 차감한 이후 결제 승인 (`/payments/confirm`) 을 통해 PG 결제를
      진행하는 방식
    - 장점: 주문 자원이 차감된 이후 결제가 승인되기 때문에 주문 자원 부족 또는 SAGA 오류에 의해 SAGA가 실패하여 주문시 실패되더라도 결제 취소가 필요없음
    - 단점: 사용자가 주문을 생성하고 결제를 처리하지 않은 경우 주문 자원은 차감되기 때문에 주문 자원 선점 문제가 발생하고 이는 실제 이커머스에서 자주 일어나는 시나리오이므로 의미 없는 주문 자원 차감과
      보상이 증가할 수 있음
2. **[대안 2: 결제 승인 이후 비동기 폴링]**
    - 설명: 결제창에서 인증을 마친 이후 `/payments/confirm`을 호출하면 SAGA 트리거를 실행하고 `202 Accepted`를 반환하고 SAGA가 모두 완료된 이후 결제 승인을 진행,
      프론트엔드에서는 폴링을 통해서 결제 성공 여부를 조회
    - 장점: 주문 자원 차감 이후 결제 승인이 이루어지기 때문에 결제 취소가 필요 없음
    - 단점: 프론트, 백엔드간의 폴링/웹소켓 구현이 필요함
3. **[대안 3: 결제 승인 이후 SAGA 트리거]**
    - 설명: `/payments/confirm`을 호출하면 먼저 PG 에 결제 승인을 처리, 결제가 성공하면 SAGA 트리거를 실행, SAGA 장애로 인해 주문이 취소된 경우 SAGA 롤백을 수행한 이후 결제를
      취소
    - 장점: 결제 이후 주문 자원이 차감되므로 자원 선점 및 불필요한 SAGA 롤백이 필요 없음
    - 단점: SAGA 실패시 결제 취소를 처리해야하며 만약 SAGA 롤백이 실패할 경우 SAGA 롤백이 완료된 이후 결제 취소가 진행되므로 운영자가 확인 후 결제 취소를 처리해야함

## 3. Decision (결정)

- **[대안 3: 결제 승인 이후 SAGA 트리거]** 를 선택
- **이유:** UX 극대화와 시스템 처리량 향상을 위해 대안 3을 선택함
  대안 3은 사용자가 결제를 진행하지 않아도 주문 자원이 차감되지 않기 때문에 불필요한 SAGA 보상을 진행하지 않으므로 시스템 부하를 줄일 수 있으며 결제 승인 이후 즉각적인 피드백(결제 성공, 실패)를 사용자가
  받을 수 있으므로 UX가 극대화됨
  SAGA 실패시에 PG 사의 결제 취소를 호출해야한다는 문제가 있지만 `[가주문(주문서) 생성 -> 주문 생성]`흐름에서 주문 자원에 대한 유효성을 재차 검증하기 때문에 SAGA 진행중 주문 자원 부족으로 인한
  SAGA 실패의 확률은 현저히 낮다 따라서 이 결제 취소 패널티보다 UX, 시스템 부하 감소로 얻는 이점이 더 크다고 판단하였다
  만약 SAGA 보상 실패로 인해 결제 취소가 자동 실행되지 않은 경우에는 대사 스케줄러를 통해 로그 및 알림을 발송하여 개발자 또는 서버 운영자가 이를 확인해 사후 처리를 진행하도록 처리한다

## 4. Consequences (결과 및 영향)

### 👍 Positive (얻게 된 것)

- 결제 완료 API의 응답 속도가 PG사 응답 속도 수준으로 최적화된다.
- 특정 마이크로서비스(예: 쿠폰 서버)가 다운되더라도, 주문과 결제는 정상적으로 이루어진다

### 👎 Negative (잃은 것 / 감당할 것)

- 비동기 차감 중 에러 발생 시, 주문 자원을 복구하고 시스템이 스스로 PG 결제 취소 API를 호출하는 복잡한 보상 트랜잭션 로직이 강제된다.
- 모든 롤백이 실패하는 최악의 장애에 대비해 스케줄러 기반의 수동 알림 모니터링이 필요하다.
