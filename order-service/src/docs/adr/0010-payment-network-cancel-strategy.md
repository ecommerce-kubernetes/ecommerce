# ADR-0010: 결제 승인시 데이터 정합성 보장을 위한 동기식 망 취소 및 상태 관리 전략

- **Status:** Accepted
- **Date:** 2026-06-17
- **Author:** 최민식
- **Tags:** #Payment, #Consistency, #ErrorHandling
-
## 1. Context (배경 및 문제 상황)

결제 처리는 PG사(외부 시스템)과 주문/결제 DB(내부 시스템)의 처리로 이루어지는데 이 둘은 하나의 트랜잭션으로 묶어 원자적으로 처리할 수 없음
만약 PG사 승인은 성공(결제 성공)하였는데 내부 DB 저장중 에러가 발생할 경우 사용자의 돈은 빠져나갔지만 주문은 실패 처리 되는 문제가 발생함
따라서 PG사 오류 발생시 또는 내부 DB 오류 발생시에 대한 명확한 에러 처리 정책(망 취소)가 필요함

## 2. Alternatives (고려했던 대안들)

1. **[대안 1: 결제 실패 또는 DB 저장 실패시 그대로 예외를 던지고 대사 스케줄러에 책임을 위임]**
    - 설명: PG사 오류 또는 데이터베이스 저장시 발생한 오류를 그대로 던지고 대사 스케줄러가 `READY` 상태의 `Payment`를 조회하여 롤백(환불) 처리를 진행함
    - 장점: 구현이 간단하고 대사 스케줄러를 통해 환불 처리가 가능함
    - 단점: 사용자가 즉각적인 결제 실패 이유를 확인할 수 없고 즉각적인 환불 처리 또한 할 수 없음
2. **[대안 2: 동기식 망 취소 이후 대사 스케줄러가 이중으로 처리]**
    - 설명: 결제 실패 또는 내부 DB 저장 실패시 동기식 망 취소 로직을 수행하고 PG사 타임아웃과 같은 알 수 없는 에러가 발생한 경우 대사 스케줄러를 통한 상태 동기화를 수행함
    - 장점: 사용자는 즉각적인 결제 실패 이유를 확인할 수 있고 결제를 즉각 취소 하기때문에 사용자의 돈을 보호할 수 있으며 데이터 정합성을 유지할 수 있음
    - 단점: 복잡한 망취소 로직과 예외 처리, 대사 스케줄러 구현이 요구됨

## 3. Decision (결정)

- **[대안 2: 동기식 망 취소 이후 대사 스케줄러가 이중으로 처리]** 를 선택
- **이유:** 결제에 있어서 사용자의 금전적 피해 서비스 신뢰도에 직결되기 때문에 개발 복잡도가 증가하더라도 유령 결제를 차단할 수 있도록 동기식 망취소를 도입
또한 장애 상황에 있어서는 대사 스케줄러를 통해 타임아웃 또는 PG사 오류와 같이 결제 상태가 미상인 경우 대사 스케줄러를 통해 결제 상태를 우선 확인 한 뒤 후처리를 진행하여 데이터 정합성을 맞춤

## 4. Consequences (결과 및 영향)

### 👍 Positive (얻게 된 것)
- 금전적 정합성 보장: PG사 성공 후 내부 에러 발생 시 즉시 망취소를 수행하여 유령 결제 방지
- 상태의 명확성: READY -> DONE/FAILED/CANCELED의 상태 전이를 명확히 관리하여 추후 정산 대사 효율성을 높힘
- 시스템 복원력: PG사 통신으로 인해 발생한 문제에 대해서 대사 스케줄러를 통한 복구가 진행되므로 일시적인 네트워크 장애와 같은 문제를 대처 가능

### 👎 Negative (잃은 것 / 감당할 것)
- 복잡한 Facade 로직: try-catch와 복잡한 예외 분기가 파사드에 포함되어 구현 난이도가 높아짐
- 스케줄러 운영: 대사 스케줄러(Reconciliation Worker)가 필수로 동작해야 하며, 이를 위한 운영 모니터링이 필요함.
