# 주문 서비스 용어 사전

> 본 용어 사전은 주문 애플리케이션 서비스의 유스케이스 명세서와 도메인 모델 명세서에서 사용하는 주요 비즈니스 용어를 정의하고, 용어 간 의미와 사용 범위를 일관되게 유지하기 위한 기준이다.

## 2. 주문 핵심 용어

| 용어      | 영문              | 유형    | 설명                                                                   | 비고                             |
|---------|-----------------|-------|----------------------------------------------------------------------|--------------------------------|
| 장바구니    | Cart            | 애그리거트 | 사용자가 주문하기 전에 구매 예정 상품을 담아두는 공간이다. 사용자별로 하나의 장바구니를 가지며 장바구니 항목을 관리한다. | Aggregate Root                 |
| 장바구니 항목 | CartItem        | 엔티티   | 장바구니에 담긴 개별 상품과 구매 수량을 나타낸다.                                         | productVariantId, quantity 관리  |
| 주문서     | OrderSheet      | 애그리거트 | 실제 주문 생성 전에 상품, 배송지, 쿠폰, 포인트 등의 주문 정보를 하나의 주문 단위로 관리하는 임시 주문 데이터이다.  | 주문 생성 전 단계                     |
| 주문서 항목  | OrderSheetItem  | 엔티티   | 주문서에 포함된 개별 상품의 상품 정보, 가격, 옵션, 수량 및 상품 쿠폰 정보를 관리한다.                  | 주문 생성 시 OrderItem으로 이어짐        |
| 주문      | Order           | 애그리거트 | 주문서의 최종 검증을 거쳐 생성된 실제 주문을 나타내며, 주문 상태와 주문 금액 및 주문 항목을 관리한다.          | Aggregate Root                 |
| 주문 항목   | OrderItem       | 엔티티   | 실제 주문에 포함된 개별 상품의 상품 정보, 가격, 쿠폰, 수량, 옵션 및 금액 정보를 관리한다.               | Order에 소속                      |
| 주문자     | Orderer         | 값 객체  | 주문을 생성한 사용자의 식별자, 이름, 전화번호 등의 정보를 나타낸다.                              | 주문 시점 정보 보존                    |
| 배송지     | ShippingAddress | 값 객체  | 주문 상품을 수령할 수령인과 배송 주소 정보를 나타낸다.                                      | 수령인 이름/전화번호, 우편번호, 주소, 상세주소 포함 |

### 3. 상품 및 스냅샷 용어

| 용어        | 영문                    | 유형        | 설명                                                    | 비고                     |
|-----------|-----------------------|-----------|-------------------------------------------------------|------------------------|
| 상품        | Product               | 외부 도메인 개념 | 주문 대상이 되는 판매 상품이다. 주문 서비스에서는 상품 시스템에서 최신 상품 정보를 조회한다. | 상품 서비스 소유              |
| 상품 변형     | Product Variant       | 외부 도메인 개념 | 하나의 상품을 판매 단위로 식별하기 위한 개별 상품 변형이다.                    | productVariantId       |
| 상품 스냅샷    | ProductSnapshot       | 값 객체      | 주문 시점의 상품 식별자, SKU, 상품명, 썸네일 등 상품 정보를 보존한 데이터이다.      | 주문 시점 정보 보존            |
| 상품 가격 스냅샷 | ProductPriceSnapshot  | 값 객체      | 주문 시점의 정상가, 할인율, 할인 금액, 판매가를 보존한 가격 정보이다.             | 주문 생성 시점 가격 검증에 사용     |
| 상품 옵션 스냅샷 | ProductOptionSnapshot | 값 객체      | 주문 시점에 사용자가 선택한 옵션 종류와 옵션 값을 보존한 정보이다.                | 예: 색상/블랙, 사이즈/XL       |
| 판매가       | discountedPrice       | 금액        | 상품 정상가에서 상품 자체 할인을 적용한 뒤의 가격이다.                       | 주문 항목의 lineTotal 계산 기준 |
| 원가        | originalAmount        | 금액        | 할인 적용 전 상품의 원래 가격을 수량만큼 계산한 금액이다.                     | 주문/주문 항목 금액 계산에 사용     |
| 상품 할인     | itemDiscount          | 금액        | 상품 자체에 적용된 할인 금액이다.                                   | 상품 쿠폰 할인과 구분           |

### 4. 쿠폰 용어

| 용어          | 영문                        | 유형     | 설명                                                     | 비고                              |
|-------------|---------------------------|--------|--------------------------------------------------------|---------------------------------|
| 쿠폰          | Coupon                    | 도메인 개념 | 주문 금액을 할인하기 위해 적용되는 할인 수단이다.                           | 상품 쿠폰과 장바구니 쿠폰으로 구분             |
| 상품 쿠폰       | Item Coupon               | 도메인 개념 | 특정 주문 항목의 상품 금액에 적용되는 쿠폰이다.                            | 상품별 적용                          |
| 장바구니 쿠폰     | Cart Coupon               | 도메인 개념 | 주문서 전체 상품의 소계를 기준으로 적용되는 쿠폰이다.                         | 주문 전체 적용                        |
| 상품 쿠폰 스냅샷   | ItemCouponSnapshot        | 값 객체   | 주문서 작성 시점의 상품 쿠폰 ID, 이름, 할인 정책 및 적용 가능 수량을 보존한 정보이다.   | 주문서에 저장                         |
| 장바구니 쿠폰 스냅샷 | CartCouponSnapshot        | 값 객체   | 주문서 작성 시점의 장바구니 쿠폰 ID, 이름, 할인 정책 및 최소 결제 금액을 보존한 정보이다. | 주문서에 저장                         |
| 적용 상품 쿠폰    | AppliedItemCoupon         | 값 객체   | 실제 주문의 주문 항목에 적용이 완료된 상품 쿠폰의 식별자와 이름을 보관한다.            | OrderItem에 사용                   |
| 적용 장바구니 쿠폰  | AppliedCartCoupon         | 값 객체   | 실제 주문에 적용이 완료된 장바구니 쿠폰의 식별자와 이름을 보관한다.                 | Order에 사용                       |
| 쿠폰 할인 정책    | CouponDiscountPolicy      | 정책     | 쿠폰 적용 대상 금액을 기준으로 실제 할인 금액을 계산하는 정책이다.                 | 정액/정률 정책                        |
| 정액 할인 정책    | FixedCouponDiscountPolicy | 정책     | 대상 금액과 관계없이 지정된 고정 금액을 할인하는 정책이다.                      | discountAmount                  |
| 정률 할인 정책    | RateCouponDiscountPolicy  | 정책     | 대상 금액에 할인율을 적용하여 할인 금액을 계산하고 최대 할인 금액을 제한하는 정책이다.      | discountRate, maxDiscountAmount |
| 최소 결제 금액    | minimumPaymentAmount      | 정책 조건  | 장바구니 쿠폰을 적용하기 위해 주문 소계가 만족해야 하는 최소 금액이다.               | 장바구니 쿠폰에 적용                     |
| 쿠폰 적용 가능 수량 | applyQuantityLimit        | 정책 조건  | 상품 쿠폰이 할인을 적용할 수 있는 최대 상품 수량이다.                        | 주문 수량보다 작으면 제한 수량까지만 할인         |
| 쿠폰 정책 변경    | Coupon Policy Changed     | 검증 상태  | 주문서 생성 당시 보관한 쿠폰 정책과 현재 쿠폰의 정책이 달라진 상태이다.              | 주문 수량보다 작으면 제한 수량까지만 할인         |

### 5. 포인트 및 금액 용어

| 용어           | 영문                 | 유형    | 설명                                                    | 비고                         |
|--------------|--------------------|-------|-------------------------------------------------------|----------------------------|
| 포인트          | Point              | 할인 수단 | 사용자가 보유하고 주문 금액을 할인하기 위해 사용하는 금액성 자원이다.               | 주문서에서는 usedPoints로 관리      |
| 사용 포인트       | usedPoints         | 금액    | 현재 주문서 또는 주문에서 실제 할인에 사용한 포인트 금액이다.                   | 주문서 생성 시 0                 |
| 최대 사용 가능 포인트 | Max Usable Points  | 계산값   | 현재 주문서의 할인 적용 상태와 포인트 정책을 기준으로 사용할 수 있는 최대 포인트 금액이다.  | 주문서에서 계산                   |
| 포인트 사용 정책    | PointUsagePolicy   | 정책    | 주문 금액을 기준으로 해당 주문에서 사용할 수 있는 최대 포인트를 계산하는 정책이다.       | calculateAvailablePoints() |
| 주문 금액        | OrderAmount        | 값 객체  | 주문 전체의 원가, 상품 할인, 쿠폰 할인, 포인트, 최종 결제 금액을 관리하는 금액 정보이다. | Order에 포함                  |
| 주문 항목 금액     | OrderItemAmount    | 값 객체  | 개별 주문 항목의 원가, 상품 할인, 판매가, 상품 쿠폰 할인 및 최종 금액을 관리한다.     | OrderItem에 포함              |
| 항목 원가        | originalAmount     | 금액    | 주문 항목의 할인 전 상품 가격 총액이다.                               | 수량 반영                      |
| 항목 상품 할인     | itemDiscount       | 금액    | 주문 항목에 포함된 상품 자체 할인 금액이다.                             | 쿠폰 할인과 구분                  |
| 항목 판매가       | lineTotal          | 금액    | 상품 자체 할인이 적용된 후의 주문 항목 금액이다.                          | 상품 쿠폰 적용 전                 |
| 상품 쿠폰 할인     | itemCouponDiscount | 금액    | 주문 항목에 적용된 상품 쿠폰의 총 할인 금액이다.                          | lineTotal에서 차감             |
| 항목 최종 금액     | finalAmount        | 금액    | 상품 자체 할인과 상품 쿠폰 할인을 모두 반영한 주문 항목의 최종 금액이다.            | 주문 항목 기준                   |
| 최종 결제 금액     | totalPaymentAmount | 금액    | 상품 할인, 상품 쿠폰, 장바구니 쿠폰, 사용 포인트를 모두 차감한 최종 결제 금액이다.     | OrderAmount의 최종 금액         |
| 장바구니 쿠폰 할인   | cartCouponDiscount | 금액    | 주문 전체에 적용된 장바구니 쿠폰의 할인 금액이다.                          | OrderAmount에 포함            |

### 6. 주문 상태 용어

| 용어       | 영문                     | 유형     | 설명                                                 | 비고                        |
|----------|------------------------|--------|----------------------------------------------------|---------------------------|
| 주문 대기    | PENDING                | 주문 상태  | 주문이 생성되었지만 아직 최종 결제가 승인되지 않은 상태이다.                 | 최초 상태                     |
| 주문 접수    | ACCEPTED               | 주문 상태  | 결제가 최종 승인되어 주문이 정상적으로 접수되고 이후 자원 차감이 시작되는 상태이다.    | PENDING → ACCEPTED        |
| 주문 실패    | FAILED                 | 주문 상태  | 결제 시간 초과 또는 자원 차감 실패 등으로 주문을 정상적으로 완료할 수 없는 상태이다.  | PENDING/ACCEPTED → FAILED |
| 주문 완료    | COMPLETED              | 주문 상태  | 재고 감소, 쿠폰 사용 등 필요한 자원 차감이 모두 성공하여 주문이 최종 확정된 상태이다. | ACCEPTED → COMPLETED      |
| 주문 상태 전이 | Order State Transition | 도메인 규칙 | 주문의 현재 상태에 따라 허용된 상태로만 변경하는 행위이다.                  | 잘못된 전이는 차단                |

### 7. 주문 이벤트 용어

| 용어        | 영문                 | 유형      | 설명                                         | 비고                     |
|-----------|--------------------|---------|--------------------------------------------|------------------------|
| 주문 접수 이벤트 | OrderAcceptedEvent | 도메인 이벤트 | 주문이 PENDING에서 ACCEPTED로 변경되었음을 나타내는 이벤트이다. | 결제 승인 완료               |
| 주문 실패 이벤트 | OrderFailedEvent   | 도메인 이벤트 | 주문이 실패 상태로 변경되었음을 나타내는 이벤트이다.              | 결제 시간 초과 또는 자원 차감 실패 등 |
| 도메인 이벤트   | Domain Event       | 이벤트     | 도메인 객체에서 중요한 상태 변화가 발생했음을 외부에 알리는 이벤트이다.   | 주문 상태 변경 등에 사용         |

### 8. 주문 취소 및 실패 용어

| 용어       | 영문                    | 유형    | 설명                                           | 비고                      |
|----------|-----------------------|-------|----------------------------------------------|-------------------------|
| 주문 취소 정보 | OrderCancelInfo       | 값 객체  | 주문 실패 또는 취소가 발생한 사유와 발생 시각을 기록하는 정보이다.       | reason, canceledAt      |
| 취소 사유    | reason                | 정보    | 주문이 실패 또는 취소된 구체적인 사유이다.                     | OrderCancelInfo         |
| 취소 시각    | canceledAt            | 정보    | 주문 실패 또는 취소가 기록된 시각이다.                       | OrderCancelInfo         |
| 결제 시간 초과 | Payment Timeout       | 실패 사유 | 지정된 시간 내에 결제가 승인되지 않아 주문이 실패 처리되는 상황이다.      | PENDING → FAILED        |
| 주문 불가    | Order Unavailable     | 실패 사유 | 재고 부족, 판매 중지 등의 이유로 주문을 진행할 수 없는 상태이다.       | 주문서 생성/최종 검증 과정에서 발생    |
| 가격 변경    | Price Changed         | 검증 결과 | 주문서 생성 당시 저장된 가격과 최종 주문 생성 시점의 가격이 달라진 상태이다. | ProductPriceSnapshot 비교 |
| 쿠폰 정책 변경 | Coupon Policy Changed | 검증 결과 | 주문서 생성 당시의 쿠폰 정책과 최종 주문 시점의 정책이 달라진 상태이다.    | 정책/조건 불일치 검증            |

### 9. 시스템 및 외부 연동 용어

| 용어           | 영문                      | 유형     | 설명                                                 | 비고                  |
|--------------|-------------------------|--------|----------------------------------------------------|---------------------|
| 상품 시스템       | Product System          | 외부 시스템 | 상품의 최신 상품 정보, 판매 상태, 가격 및 재고 관련 정보를 제공하는 외부 시스템이다. | 장바구니/주문서/주문 생성에서 조회 |
| 회원 시스템       | User System             | 외부 시스템 | 주문자 프로필 및 사용 가능한 포인트 등의 회원 정보를 제공하는 시스템이다.         | 주문자/포인트 조회          |
| 쿠폰 시스템       | Coupon System           | 외부 시스템 | 주문서 및 주문에 적용되는 쿠폰 정보를 조회하고 쿠폰 유효성을 검증하는 시스템이다.     | 쿠폰 ID 기반 조회         |
| 외부 시스템 연동 실패 | External System Failure | 예외     | 상품/회원/쿠폰 등 외부 시스템과의 통신에 실패한 상황이다.                  | 타임아웃, 장애 등          |

| 보상 성공 처리     | `completeCompensate`       | 행위      | 현재 보상 실행을 성공 처리하고 다음 보상 대상을 결정하는 행위이다.                          | 역순 보상                                                       |

| 보상 트랜잭션      | `Compensation Transaction` | 처리      | 정방향 처리에서 성공한 자원을 원래 상태로 되돌리는 처리이다.                              | 역순 실행                                                       |
| SAGA 실패 사유   | `failureReason`            | 정보      | SAGA 또는 개별 처리의 실패 원인을 저장하는 정보이다.                                | `OrderSaga`에 저장                                             |

### 15. SAGA 실행 결과 및 멱등성 용어

| 용어       | 영문명                 | 유형       | 정의                                                                | 비고                |
|----------|---------------------|----------|-------------------------------------------------------------------|-------------------|
| 실행 대기    | `PENDING`           | 실행 상태    | SAGA 실행이 생성되었지만 아직 외부 마이크로서비스의 처리 결과를 받지 않은 상태이다.                 | 실행 생성 초기 상태       |
| 실행 성공    | `SUCCESS`           | 실행 상태    | 외부 마이크로서비스가 해당 SAGA 작업을 성공적으로 처리한 상태이다.                           | 성공 후 다음 단계 진행     |
| 실행 실패    | `FAIL`              | 실행 상태    | 외부 마이크로서비스가 해당 SAGA 작업을 실패 처리한 상태이다.                              | 정방향 실패 시 보상 시작    |
| 실행 결과    | `Execution Result`  | 도메인 개념   | 개별 SAGA 실행의 성공 또는 실패 결과이다.                                        | `SUCCESS`, `FAIL` |
| 멱등 처리    | `Idempotency`       | 처리 규칙    | 동일한 SAGA 실행 결과가 중복 수신되더라도 추가적인 상태 변경이나 중복 작업이 발생하지 않도록 처리하는 규칙이다. | 메시지 중복 소비 대비      |
| 중복 성공 처리 | `Duplicate Success` | 예외/처리 상황 | 이미 `SUCCESS`인 실행에 동일한 성공 결과가 다시 전달된 상황이다.                         | 상태 변경 없음          |
| 중복 실패 처리 | `Duplicate Failure` | 예외/처리 상황 | 이미 `FAIL`인 실행에 동일한 실패 결과가 다시 전달된 상황이다.                            | 상태 변경 없음          |

### 17. 메시지 처리 및 장애 대응 용어

| 용어            | 영문명                      | 유형     | 정의                                                                            | 비고              |
|---------------|--------------------------|--------|-------------------------------------------------------------------------------|-----------------|
| Kafka 토픽      | `Kafka Topic`            | 메시징    | SAGA 관련 요청 및 응답 메시지를 전달하는 메시지 채널이다.                                           | Kafka 사용        |
| Kafka 메시지 컨슈머 | `Kafka Message Consumer` | 메시지 처리 | Kafka에서 SAGA 응답 메시지를 수신하여 성공 또는 실패 처리 흐름으로 라우팅하는 시스템 구성 요소이다.                 | `UC-SAGA-02~05` |
| 메시지 라우팅       | `Message Routing`        | 처리     | 수신한 메시지의 헤더와 결과를 분석하여 정방향 성공, 정방향 실패, 보상 성공, 보상 실패 중 적절한 처리 흐름으로 전달하는 과정이다.   | SAGA 결과 처리      |
| 데드 레터         | `Dead Letter`            | 장애 처리  | 반복적인 메시지 처리 실패나 보상 실패와 같이 자동 처리가 어려운 메시지를 별도 경로로 전달하여 후속 조치를 수행하기 위한 처리 방식이다. | 관리자 개입 가능       |
| 관리자 개입        | `Manual Intervention`    | 장애 처리  | 자동 보상으로 해결할 수 없는 치명적인 오류에 대해 운영자가 직접 상태를 확인하고 복구하는 처리이다.                      | `FAILED` SAGA   |
| 영구 실패         | `Permanent Failure`      | 실패 상태  | 보상 처리까지 실패하여 자동으로 정상 상태로 복구하기 어려운 상태이다.                                       | 관리자 개입 필요       |
