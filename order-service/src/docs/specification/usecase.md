# 장바구니 유스케이스

## 장바구니 상품 추가

### 목적

사용자가 선택한 상품을 장바구니에 추가한다.

### 조건

- 사용자는 로그인 되어있어야 한다.
- 추가하려는 상품은 판매중이어야 한다.

### 기본 흐름

1. 사용자가 요청한 상품의 정보를 조회한다.
2. 상품이 장바구니에 추가할 수 있는 상품인지 검증한다.
3. 장바구니에 항목을 추가한다.
4. 변경된 장바구니를 저장한다.

#### 대안 흐름

- **1a. 장바구니가 존재하지 않는경우**
    1. 기본 흐름 2까지 진행한다
    2. 사용자 식별자로 장바구니를 생성한뒤 기본흐름 3을 진행한다
- **2a. 상품 조건이 만족하지 않는 경우**
    1. 예외를 발생시키고 흐름을 종료한다.

## 장바구니 조회

사용자의 장바구니 전체 항목 정보를 반환한다.

### 조건

- 사용자는 로그인 되어있어야 한다.

### 기본 흐름

1. 사용자의 장바구니를 조회한다.
2. 조회한 항목의 상품 식별자로 상품 정보를 조회한다.
3. 조회한 상품 정보와 함께 장바구니 항목의 최신 정보를 반환한다.

### 대안 흐름

- **1a. 장바구니가 없는 경우**
    1. 빈 리스트를 반환한다.
- **2a. 장바구니에 항목이 없는 경우**
    1. 빈 리스트를 반환한다.
- **3a. 장바구니의 항목이 상품 조회에서 누락된 경우**
    1. 누락된 항목은 항목 정보만 포함하여 판매 불가 상태로 반환한다.
- **4a. 장바구니에 담긴 항목이 판매 불가능한 경우**
    1. 판매 불가능한 항목은 판매 불가 상태로 반환한다.

## 장바구니 항목 조회

사용자의 장바구니 항목을 조회한다

### 조건

- 사용자는 로그인 되어있어야 한다.

### 기본 흐름

1. 사용자의 장바구니를 조회한다.
2. 장바구니에서 조회 항목을 찾는다.
3. 찾은 항목의 상품 식별자로 상품 정보를 조회한다.
4. 조회한 상품 정보와 함께 장바구니 항목의 최신 정보를 반환한다.

### 대안 흐름

- **1a. 장바구니가 없는 경우**
    1. 예외를 발생시키고 흐름을 종료한다.
- **2a. 장바구니에 조회 항목이 없는 경우**
    1. 예외를 발생시키고 흐름을 종료한다.

## 장바구니 항목 수량 변경

사용자의 장바구니 항목의 수량을 변경한다.

3. 변경된 장바구니 항목을 반환한다.

### 대안 흐름

- **1a. 장바구니에 변경할 항목이 없는 경우**
    1. 예외를 발생시키고 흐름을 종료한다.

# 주문서 유스케이스

## 바로 구매 주문서 생성

주문 상품과 수량을 통해 바로 구매 주문서를 생성한다.

### 행위자

- 인가된 사용자(Customer)

### 목적

- 상품 상세 페이지에서 단일 상품의 수량을 선택하여 즉시 결제를 진행하기 위한 임시 주문서를 생성한다.

### 선행 조건

- 사용자는 로그인 되어있어야 하며, 시스템에 존재하는 회원이여야 한다.
- 시스템은 외부 서비스와 통신 가능한 상태여야 한다.

### 기본 흐름

1. 사용자가 상품 식별자와 구매 수량을 포함하여 바로 구매 주문서 생성을 요청한다.
2. 시스템은 요청한 사용자 식별자로 회원 정보를 조회한다.
3. 시스템은 요청된 상품 식별자로 상품 정보를 조회한다.
4. 시스템은 상품이 판매 중 상태인지, 요청 수량이 현재 재고를 초과하지 않는지 검증한다.
5. 시스템은 회원의 대표 배송지 정보와 조회된 상품 정보를 바탕으로 주문서를 생성한다.
6. 시스템은 생성된 주문서를 저장소에 저장하고, 주문서 정보를 사용자에게 반환한다.

### 대안 흐름

- **1a. 사용자의 대표 배송지가 존재하지 않는 경우**
    1. 시스템은 배송지 정보를 비워둔 주문서를 생성하고 `기본 흐름 6`을 진행한다.

### 예외 흐름

- **2a. 존재하지 않는 사용자인 경우**
    1. 시스템은 예외를 발생시키고 흐름을 즉시 종료한다.
- **2b. 주문하려는 상품이 존재하지 않거나 판매중이 아닌 경우**
    1. 시스템은 예외를 발생시키고 흐름을 즉시 종료한다.
- **2c. 주문 수량이 현재 남은 상품 재고를 초과하는 경우**
    1. 시스템은 예외를 발생시키고 흐름을 즉시 종료한다.

### 사후 조건

- 데이터베이스에 만료시간이 설정된 바로 구매 주문서가 저장된다.

## 주문서 조회

주문서 정보를 조회한다.

### 행위자

- 인가된 사용자(Orderer)

### 목적

- 주문서 페이지에서 사용자가 생성한 주문서 정보를 조회한다.

### 선행 조건

- 사용자는 로그인 되어있어야 하며, 시스템에 존재하는 회원이여야 한다.
- 시스템은 외부 서비스와 통신 가능한 상태여야 한다.

### 기본 흐름

1. 사용자가 주문서 식별자를 통해 주문서 조회를 요청한다.
2. 시스템은 주문서 식별자와 요청한 사용자 식별자를 통해 주문서를 조회한다.
3. 주문서가 만료되었는지 검증한다.
4. 사용자 식별자로 회원 보유 포인트를 조회한다.
5. 주문서 도메인과 회원 보유 포인트를 조합하여 주문서 조회 응답 스펙에 맞게 반환한다.

### 대안 흐름

- **1a. 회원 보유 포인트 조회 장애시**
    1. 회원 보유 포인트를 0원으로 설정해 주문서 조회 응답 스펙에 맞게 반환한다.

### 예외 흐름

- **2a. 주문서를 찾을 수 없는 경우**
    1. 시스템은 예외를 발생시키고 흐름을 즉시 종료한다.
- **2b. 주문서가 만료된 경우**

6. 주문서 도메인과 회원 보유 포인트를 조합하여 응답 스펙에 맞게 반환한다.
