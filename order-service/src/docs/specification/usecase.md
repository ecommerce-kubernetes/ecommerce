## 3. 유스케이스 상세 명세 (UseCase Specifications)

### 3.1. [UC-CART-01] 장바구니 상품 추가

1. 기본 정보
    - 목적: 사용자가 선택한 하나 이상의 상품을 장바구니에 추가한다.
    - 행위자: 인가된 사용자
    - 선행 조건:
        - 사용자는 시스템에 로그인 되어있어야 한다.
        - 상품 시스템과 통신이 가능해야한다.
    - 사후 조건
        - 선택한 상품이 사용자의 장바구니에 저장된다.

2. 기본흐름
    1. [행위자]: 장바구니에 추가할 상품 식별자 목록과 수량 정보를 포함하여 항목 추가를 요청한다.
    2. [시스템]: 입력받은 상품 식별자들을 이용해 상품 시스템(Product Port)에서 최신 상품 정보를 조회한다.
    3. [시스템]: 조회된 상품들이 현재 판매 가능한 상태(ON_SALE)인지 검증한다.
    4. [시스템]: 사용자의 식별자로 기존 장바구니를 조회하거나, 없을 경우 새로 생성한다.
    5. [시스템]: 장바구니에 항목을 추가하거나 기존 항목의 수량을 증가시킨다
    6. [시스템]: 변경된 장바구니를 데이터베이스에 저장한다.
    7. [시스템]: 추가된 장바구니 항목의 식별자 목록을 반환한다.

3. 대안 흐름
    - [A-1] 기존 장바구니가 존재하지 않는 경우 (기본흐름 4번에서 분기)
        1. [시스템]: 사용자의 식별자로 새로운 빈 장바구니를 생성한다.
        2. [시스템]: 장바구니 생성 후, 기본 흐름 5번으로 복귀하여 상품을 추가한다.

4. 예외 흐름
    - [E-1] 외부 시스템 연동 실패 (기본 흐름 2번에서 발생)
        1. [시스템]: 상품 시스템의 타임아웃, 서킷 브레이커 오픈 등의 통신 오류를 감지한다.
        2. [시스템]: 예외 응답(PortException 등)을 반환하고 흐름을 즉시 종료한다.
    - [E-2] 판매 불가 상품 추가 시도 (기본 흐름 3번에서 발생)
        1. [시스템]: 상품이 존재하지 않거나, 판매 중(ON_SALE)이 아님을 검증한다.
        2. [시스템]: '판매 불가능한 상품' 예외를 반환하고 흐름을 즉시 종료한다.
    - [E-3] 장바구니 도메인 제약조건 위반 (기본 흐름 5번에서 발생)
        1. [시스템]: 장바구니 항목 최대 개수 초과(예: 20개), 상품의 최대 구매 가능 수량 초과 등의 도메인 예외를 감지
        2. [시스템]: 도메인 예외 메시지를 반환하고 흐름을 즉시 종료한다.

### 3.2 [UC-CART-02] 장바구니 전체 조회

1. 기본 정보
    - 목적: 사용자의 장바구니 전체 항목을 최신 상품 정보 및 재고 상태와 조합하여 반환한다.
    - 행위자: 인가된 사용자
    - 선행 조건: 사용자는 로그인되어 있어야 한다.
    - 사후 조건: 데이터 상태 변경 없음 (Read-only).

2. 기본 흐름
    1. [행위자]: 장바구니 조회를 요청한다.
    2. [시스템]: 사용자 식별자를 통해 장바구니 항목 목록을 데이터베이스에서 조회한다.
    3. [시스템]: 조회된 장바구니 항목들의 상품 식별자를 추출하여 상품 시스템(Product Port)에서 최신 상품 정보를 조회한다.
    4. [시스템]: 장바구니 항목 데이터와 최신 상품 정보를 결합하여 각 항목의 구매 가능 여부(AVAILABLE, LACK_OF_STOCK, NOT_FOR_SALE)를 판단한다.
    5. [시스템]: 구매 가능 상태가 포함된 장바구니 항목 목록을 반환한다.

3. 대안 흐름
    - [A-1] 장바구니 내역이 없는 경우 (기본 흐름 2번에서 분기)
        1. [시스템]: 사용자의 장바구니 데이터가 없거나 비어있음을 확인한다.
        2. [시스템]: 외부 상품 조회를 생략하고 빈 장바구니 응답을 즉시 반환한다.
    - [A-2] 장바구니에 담긴 상품이 삭제되거나 조회 불가능한 경우 (기본 흐름 4번에서 분기)
        1. [시스템]: 장바구니 항목에 해당하는 상품 정보가 상품 시스템의 응답에서 누락된 것을 감지한다.
        2. [시스템]: 해당 항목의 상태를 '판매 불가(NOT_FOR_SALE)' 및 '알 수 없는 상품'으로 표기하여 반환 목록에 포함한다.
    - [A-3] 재고 부족 또는 판매 중지 상태인 경우 (기본 흐름 4번에서 분기)
        1. [시스템]: 상품이 판매 중지 상태이거나, 장바구니에 담은 수량이 현재 재고보다 많은 것을 감지한다.
        2. [시스템]: 해당 항목의 상태를 각각 '판매 불가(NOT_FOR_SALE)' 또는 '재고 부족(LACK_OF_STOCK)'으로 표기하여 반환 목록에 포함한다.

4. 예외 흐름
    - [E-1] 외부 상품 시스템 연동 실패 (기본 흐름 3번에서 발생)
        1. [시스템]: 상품 시스템 조회 중 오류가 발생한다.
        2. [시스템]: 외부 시스템 장애 예외를 반환하고 흐름을 즉시 종료한다.

## #3.3. [UC-CART-03] 장바구니 단일 항목 조회

1. 기본 정보
    - 목적: 장바구니 내 특정 항목 1개의 상세 정보와 최신 상품 상태를 반환한다.
    - 행위자: 인가된 사용자
    - 선행 조건: 사용자는 로그인되어 있어야 한다.

2. 기본 흐름
    1. [행위자]: 특정 장바구니 항목 식별자(cartItemId)를 통해 조회를 요청한다.
    2. [시스템]: 사용자 식별자와 항목 식별자를 이용해 장바구니 항목을 조회한다.
    3. [시스템]: 조회된 항목의 상품 식별자로 상품 시스템(Product Port)에서 최신 상품 정보를 조회한다.
    4. [시스템]: 항목 데이터와 상품 정보를 결합하여 구매 가능 상태를 판단한다.
    5. [시스템]: 최신 정보가 반영된 단일 장바구니 항목 데이터를 반환한다.

3. 대안 흐름 (Alternative Flows)
    - [A-1] 상품 정보 누락 또는 판매 불가 상태 (기본 흐름 4번에서 분기)
        - [시스템]: UC-CART-02의 [A-2], [A-3]과 동일한 방식으로 상태를(NOT_FOR_SALE, LACK_OF_STOCK) 판별하여 반환한다.

4. 예외 흐름 (Exception Flows)
    - [E-1] 장바구니 항목을 찾을 수 없는 경우 (기본 흐름 2번에서 발생)
        1. [시스템]: 요청한 식별자의 항목이 존재하지 않거나 해당 사용자의 소유가 아님을 감지한다.
        2. [시스템]: 항목을 찾을 수 없다는 예외를 반환하고 흐름을 종료한다.
    - [E-2] 외부 상품 시스템 연동 실패 (기본 흐름 3번에서 발생)
        1. [시스템]: 통신 예외를 반환하고 즉시 종료한다.

### 3.4. [UC-CART-04] 장바구니 항목 수량 변경

1. 기본 정보
    - 목적: 장바구니에 담긴 특정 항목의 구매 예정 수량을 수정한다.
    - 행위자: 인가된 사용자
    - 선행 조건: 사용자는 로그인되어 있어야 한다.

2. 기본 흐름 (Normal Flow)
    1. [행위자]: 변경할 장바구니 항목 식별자와 새로운 수량을 전달하여 수량 변경을 요청한다.
    2. [시스템]: 사용자 식별자와 항목 식별자를 이용해 장바구니 항목을 조회한다.
    3. [시스템]: 항목의 상품 식별자로 상품 시스템(Product Port)에서 최신 상품 정보를 조회한다.
    4. [시스템]: 해당 상품이 판매 가능한 상태(ON_SALE)인지 검증한다.
    5. [시스템]: 장바구니 항목의 수량을 새로운 수량으로 갱신한다 (최대 수량 등의 도메인 규칙 검증 포함).
    6. [시스템]: 변경 사항을 데이터베이스에 저장하고, 갱신된 항목 식별자를 반환한다.

3. 대안 흐름 (Alternative Flows)
   (이 유스케이스는 기본 흐름 외의 정상 대안 흐름이 없음)

4. 예외 흐름 (Exception Flows)
    - [E-1] 장바구니 항목을 찾을 수 없는 경우 (기본 흐름 2번에서 발생)
        1. [시스템]: 항목을 찾을 수 없다는 예외를 반환하고 흐름을 종료한다.
    - [E-2] 외부 상품 시스템 연동 실패 (기본 흐름 3번에서 발생)
        1. [시스템]: 통신 예외를 반환하고 즉시 종료한다.
    - [E-3] 수량 변경 불가 상품 (기본 흐름 4번에서 발생)
        1. [시스템]: 상품이 판매 중이 아니거나 존재하지 않음을 감지한다.
        2. [시스템]: 판매 불가 예외를 반환하고 흐름을 즉시 종료한다.
    - [E-4] 도메인 제약조건 위반 (기본 흐름 5번에서 발생)
        1. [시스템]: 변경하려는 수량이 1 미만이거나, 상품별 최대 허용 한도를 초과함을 감지한다.
        2. [시스템]: 수량 제한 예외를 반환하고 흐름을 즉시 종료한다.

### 3.5. [UC-CART-05] 장바구니 항목 삭제

1. 기본 정보
    - 목적: 장바구니에 담긴 특정 항목(들)을 사용자 의도에 따라 삭제한다.
    - 행위자: 인가된 사용자
    - 선행 조건: 사용자는 로그인되어 있어야 한다.

2. 기본 흐름 (Normal Flow)
    - [행위자]: 삭제할 장바구니 항목 식별자 목록을 전달하여 삭제를 요청한다.
    - [시스템]: 사용자 식별자를 통해 장바구니를 조회하고, 요청된 식별자들에 해당하는 항목들을 장바구니에서 제거한다.
    - [시스템]: 변경된 장바구니 상태를 데이터베이스에 저장한다.
    - [시스템]: 성공(No Content) 응답을 반환한다.

3. 대안 흐름 (Alternative Flows)
   (이 유스케이스는 기본 흐름 외의 정상 대안 흐름이 없음)

4. 예외 흐름 (Exception Flows)
    - [E-1] 삭제할 항목이 장바구니에 없는 경우 (기본 흐름 2번에서 발생)
        1. [시스템]: 요청한 식별자 중 일부 또는 전체가 현재 장바구니에 존재하지 않음을 감지한다.
        2. [시스템]: 항목을 찾을 수 없다는 예외를 반환하고 흐름을 종료한다.

# 주문서 유스케이스

## 장바구니 주문서 생성

장바구니에 담긴 항목을 주문서로 생성한다.

### 행위자

- 인가된 사용자(Customer)

###

- 장바구니 페이지에서 장바구니에 담긴 항목을 선택하여 임시 주문서를 생성한다.

### 선행 조건

- 사용자는 로그인 되어있어야 하며, 시스템에 존재하는 회원이여야 한다.
- 시스템은 외부 서비스와 통신 가능한 상태여야 한다.

### 기본 흐름

1. 사용자가 장바구니 항목 식별자를 포함하여 장바구니 주문서 생성을 요청한다.
2. 시스템은 요청한 사용자 식별자로 회원 정보를 조회한다.
3. 시스템은 요청된 장바구니 항목 식별자로 장바구니 항목 정보를 조회한다
4. 시스템은 조회된 장바구니 항목의 상품 식별자로 상품 정보를 조회한다.
5. 시스템은 상품이 판매 중 상태인지, 요청 수량이 현재 재고를 초과하지 않는지 검증한다.
6. 시스템은 회원의 대표 배송 정보와 조회된 상품 정보를 바탕으로 주문서를 생성한다.
7. 시스템은 주문서를 저장하고 주문서 정보를 사용자에게 반환한다.

### 대안 흐름

- **1a. 사용자의 대표 배송지가 존재하지 않는 경우**

# 주문 유스케이스

## 주문 생성

### 목적

주문서를 기반으로 주문을 생성한다.

### 행위자

- 인가된 사용자(Orderer)

### 선행 조건

- 사용자는 로그인 되어있어야 하며, 시스템에 존재하는 회원이여야 한다.
- 시스템은 외부 서비스와 통신 가능한 상태여야 한다.

### 기본 흐름

1. 사용자가 주문서 식별자를 통해 주문 생성을 요청한다.
2. 시스템은 사용자 아이디와 주문서 식별자를 통해 주문서를 조회한다.
3. 주문서의 주문 항목 식별자로 상품을 조회하여 수량과 상태를 검증한다.
4. 주문서의 주문 항목에 상품 쿠폰이 적용되어 있다면 쿠폰을 조회하여 할인 금액을 검증한다.
5. 주문서에 장바구니 쿠폰이 적용되어있다면 장바구니 쿠폰을 조회하여 할인 금액을 검증한다.
6. 주문서에 포인트가 적용되어있다면 사용자 가용 포인트가 충분한지 검증한다.
7. 최종 주문 가격 정보를 검증한다.
8. 주문을 결제 대기(`PENDING`) 상태로 생성한다.
9. 주문을 저장하고 주문 정보를 반환한다.

- 데이터베이스에 주문이 저장된다.

    1. 시스템은 예외를 발생시키고 흐름을 즉시 종료한다.
- **1c. 주문 상품 검증 실패시**
    1. 시스템은 예외를 발생시키고 흐름을 즉시 종료한다.
- **1d. 쿠폰 검증 실패시**

# 결제 유스케이스

## 결제 생성

### 목적

주문의 결제를 생성한다.

### 행위자

- 인가된 사용자(User)

### 선행 조건

- 사용자는 로그인 되어있어야 하며, 시스템에 존재하는 회원이여야 한다.
- 시스템은 외부 서비스와 통신 가능한 상태여야 한다.

### 기본 흐름

1. 사용자가 결제를 생성할 주문 아이디를 통해 결제 생성을 요청한다.
2. 시스템은 주문을 조회한다.
3. 시스템은 주문이 결제 가능 상태인지 검증한다.
4. 시스템은 결제를 결제 준비(`READY`)상태의 결제를 생성한다.
5. 결제를 저장하고 결제 정보를 반환한다.

### 사후 조건

- 데이터베이스에 결제가 저장된다.

### 예외 흐름

- **1a. 주문을 찾을 수 없는 경우**
    1. 시스템은 예외를 발생시키고 흐름을 즉시 종료한다.
- **1b. 주문이 결제를 할 수 없는 상태인 경우**
    1. 시스템은 예외를 발생시키고 흐름을 즉시 종료한다.

## 결제 승인

### 목적

결제를 승인한다

### 행위자

- 인가된 사용자(User)

### 선행 조건

- 사용자는 로그인 되어있어야 하며, 시스템에 존재하는 회원이여야 한다.
- 시스템은 외부 서비스와 통신 가능한 상태여야 한다.

### 기본 흐름

1. 사용자가 결제 식별자, 결제 키, 결제사 정보를 통해 결제 승인을 요청한다.
2. 시스템은 결제를 조회한다.
3. 시스템은 결제를 승인 대기(`APPROVAL_PENDING`) 상태로 변경한다.
4. 시스템은 결제사 PG에 결제 승인을 요청한다.
5. 시스템은 결제사 PG 승인 응답을 통해 결제를 승인 처리한다.
6. 시스템은 변경 내용을 저장하고 응답을 반환한다.

### 사후 조건

- 데이터베이스에 결제 내역이 저장된다.

### 예외 흐름

- **1a. 결제를 찾을 수 없는 경우**
    1. 시스템은 예외를 발생시키고 흐름을 즉시 종료한다.
- **1b. 결제가 승인 대기로 변경할 수 없는 경우**
  1-1. 결제 상태가 준비 상태가 아닌 경우
    - 시스템은 예외를 발생시키고 흐름을 즉시 종료한다.
      1-2. 결제 금액이 승인 금액과 다른 경우
    - 시스템은 결제를 실패 처리한다.
    - 시스템은 예외를 발생시키고 흐름을 즉시 종료한다.
- **1c. 지원하지 않는 결제사인 경우, 서킷 브레이커 차단, PG 사 400번대 에러 응답 반환시**
    1. 시스템은 해당 결제를 실패 처리한다.
    2. 시스템은 예외를 발생시키고 흐름을 종료한다.
- **1d. 지원하지 않는 결제 방식인 경우, 도메인 금액 검증에 실패, DB 커밋 오류 발생시**
    1. 시스템은 망 취소를 진행한다.
    2. 시스템은 망 취소 후 결제를 실패 처리한다.
        - 망 취소 실패시 시스템은 결제 상태를 변경하지 않고 대사 로직에 흐름을 넘긴다.
        - 시스템은 예외를 발생시키고 흐름을 종료한다.
- **1f. 통신 타임아웃, PG사 500번대 에러 응답 반환시**
    1. 시스템은 결제 상태를 변경하지 않고 대사 로직에 흐름을 넘긴다.
    2. 시스템은 예외를 발생시키고 흐름을 종료한다.
