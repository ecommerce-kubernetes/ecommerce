# 도메인 모델

## OrderService

- **목적:** 사용자의 장바구니 상품 담기와 주문서 작성, 최종 주문 생성 및 결제 연동까지 전체 구매 흐름을 관리한다.
- **특징:** 분산 트랜잭션 처리를 위해 오케스트레이션 기반의 SAGA 패턴을 적용하여 주문 서비스가 재고, 쿠폰, 포인트 트랜잭션 흐름을 제어한다.

### 주요 도메인

- **장바구니(Cart) :** 사용자의 구매 대기중인 상품 목록을 관리
- **주문서(OrderSheet) :** 주문 생성 전 쿠폰 적용 및 포인트 적용 등 할인 정책 관리와 배송 정보, 주문 예상 금액을 계산하여 저장하는 임시 주문.
- **주문(Order)  :** 사용자의 최종 구매 확정 내역 및 상태 관리
- **결제(Payment) :** 해당 주문의 결제 정보, PG 사의 결제 정보 및 상태 관리

## 엔티티

### 장바구니(Cart)

사용자 1명당 1개의 생명주기를 갖는 장바구니 애그리거트 루트.

#### 속성

| 필드명       | 타입             | 설명                    |
|-----------|----------------|-----------------------|
| id        | Long           | 장바구니 식별자              |
| userId    | Long           | 장바구니의 소유자 식별자         |
| cartItems | List<CartItem> | 장바구니에 담긴 개별 상품 항목 리스트 |

#### 행위

- 장바구니 생성: 장바구니를 생성한다.
- 항목 추가: 장바구니에 상품을 추가한다.
- 항목 삭제: 장바구니에 담긴 항목을 삭제한다.
- 항목 수량 변경: 장바구니에 담긴 항목의 수량을 변경한다.

#### 규칙

- 장바구니를 생성할때 유저 식별자가 필요하다.
- 장바구니에 추가하려는 항목이 이미 장바구니에 존재하는 경우 기존 항목의 수량을 증가시킨다.
- 장바구니의 최대 항목 개수를 초과하는 경우 더이상 장바구니에 항목을 추가할 수 없다.
- 장바구니에 존재하지 않는 항목은 수량을 변경할 수 없다.
- 장바구니에 존재하지 않는 항목은 삭제할 수 없다.

### 장바구니 항목(CartItem)

장바구니에 담긴 개별 상품 정보를 관리하는 하위 엔티티

#### 속성

| 필드명              | 타입      | 설명          |
|------------------|---------|-------------|
| id               | Long    | 장바구니 항목 아이디 |
| cart             | Cart    | 장바구니        |
| productVariantId | Long    | 상품 변형 아이디   |
| quantity         | Integer | 담은 수량       |

#### 행위

- create (항목 생성): 장바구니 항목을 생성한다.
- addQuantity (수량 추가): 항목의 수량을 추가한다.
- updateQuantity (수량 변경): 항목의 수량을 변경한다.

#### 규칙

- 장바구니 항목을 생성할때 상품 판매 단위 식별자가 필요하다.
- 장바구니 항목을 생성할때 수량 정보가 필요하다.
- 장바구니 항목을 생성할때 수량이 최대 한계치를 초과할 수 없다.
- 장바구니 항목을 생성할때 항목의 수량은 최소 1개 이상이여야 한다.
- 장바구니 항목의 수량을 추가할때 최대 한계치를 초과할 수 없다.
- 장바구니 항목의 수량을 변경할때 수량은 최소 1개 이상이여야 한다.
- 장바구니 항목의 수량을 변경할때 수량은 최대 한계치를 초과할 수 없다.

### 주문서 (OrderSheet)

임시 주문 데이터를 저장하는 주문서 애그리거트 루트.

#### 속성

| 필드명             | 타입                   | 설명        |
|-----------------|----------------------|-----------|
| id              | Long                 | 주문서 아이디   |
| orderer         | Orderer              | 주문자 정보    |
| shippingAddress | ShippingAddress      | 배송 정보     |
| items           | List<OrderSheetItem> | 주문 상품 리스트 |
| cartCoupon      | CartCouponSnapshot   | 장바구니 쿠폰   |
| usedPoints      | Money                | 적용 포인트 금액 |
| expiresAt       | LocalDateTime        | 주문서 만료 시간 |

#### 행위

- 주문서 생성: 주문서를 생성한다.
- 배송 정보 변경: 주문서의 배송 정보를 변경한다.
- 주문 항목 상품 쿠폰 적용: 주문 항목을 찾아 상품 쿠폰을 적용한다.
- 장바구니 쿠폰 적용: 장바구니 쿠폰을 적용한다.
- 포인트 적용: 사용할 포인트를 적용한다.
- 장바구니 쿠폰 할인 금액 계산: 주문서에 적용된 장바구니 쿠폰 할인 금액을 계산한다.
- 최대 적용 가능 포인트 계산: 주문서의 최대 적용 가능 포인트를 계산한다.
- 총 주문 항목 상품 원가격 총액 계산: 전체 주문 항목의 상품 원 가격 총액을 계산한다.
- 총 주문 항목 상품 할인 가격 총액 계산: 전체 주문 항목의 상품 할인 금액 총액을 계산한다.
- 총 주문 항목 상품 쿠폰 할인 가격 총액 계산: 전체 주문 항목의 쿠폰 할인 금액 총액을 계산한다.
- 총 결제 금액 계산: 주문서의 총 결제 금액을 계산한다.
- 잔여 만료시간을 계산한다.
- 쿠폰이 적용된 주문 항목을 조회한다.
- 장바구니 쿠폰 적용 유무를 확인한다.
- 장바구니 쿠폰 검증: 장바구니 쿠폰 할인 정책이 변경되었는지 검증한다.
- 포인트가 최대 적용 가능 한도를 초과하는지 검증한다.

#### 규칙

- 주문서를 생성할 때 주문 항목 정보를 가격 정보가 계산된다.
- 주문서를 생성할 때 주문자 정보가 필요하다.
- 주문서를 생성할 때 하나 이상의 주문 항목이 필요하다.
- 주문서를 생성할 때 만료시간이 필요하다.
- 주문 항목 상품 쿠폰을 적용할때 동일한 상품 쿠폰을 여러 주문 항목에 중복 적용할 수 없다.
- 주문 항목 상품 쿠폰을 적용할때 주문서에 적용된 포인트 금액이 상품 쿠폰 변경으로 인해 변동된 적용 가능 포인트 한도를 초과하는 경우, 적용 가능 포인트를 한도로 적용된 포인트가 보정된다.
- 주문서에 장바구니 쿠폰을 적용할때 소계가 최소 결제 금액에 만족해야한다.
- 주문서에 장바구니 쿠폰을 적용할때 주문서에 적용된 포인트 금액이 장바구니 쿠폰 변경으로 인해 변동된 적용 가능 포인트 한도를 초과하는 경우, 적용 가능 포인트를 한도로 적용된 포인트가 보정된다.
- 주문서에 포인트를 적용할때 적용할 포인트는 최대 적용 가능 포인트를 초과할 수 없다.
- 주문서에 적용된 장바구니 쿠폰 할인 가격을 계산할 때 장바구니 쿠폰이 적용되지 않은 경우 장바구니 쿠폰 할인 금액은 0원이다.
- 주문서에 적용된 장바구니 쿠폰 할인 가격을 계산할 때 장바구니 쿠폰 할인 금액이 전체 주문 항목 최종 가격 총액을 초과하는 경우, 장바구니 쿠폰 할인 금액은 전체 주문 항목 최종 가격 총액을 한도로 적용된다.
- 주문서의 잔여 만료 시간을 계산할때 이미 만료시간이 지났다면 잔여 만료 시간이 없으므로 0의 기간을 반환한다.
- 쿠폰이 적용된 주문 항목을 조회할때 쿠폰이 적용된 주문 항목이 없다면 빈 리스트를 반환한다.

### 주문 항목(OrderSheetItem)

주문서의 상품 정보를 관리하는 하위 엔티티

#### 속성

| 필드명                | 타입                          | 설명             |
|--------------------|-----------------------------|----------------|
| id                 | Long                        | 주문서 상품 아이디     |
| productSnapshot    | ProductSnapshot             | 주문 시점 상품 정보    |
| priceSnapshot      | ProductPriceSnapshot        | 주문 시점 상품 가격 정보 |
| itemCouponSnapshot | ItemCouponSnapshot          | 적용 상품 쿠폰       |
| quantity           | Integer                     | 상품 주문 수량       |
| optionSnapshots    | List<ProductOptionSnapshot> | 주문 상품 옵션 정보 목록 |

#### 행위

- 주문 항목 생성: 주문 항목을 생성한다.
- 상품 쿠폰 적용: 주문 항목에 상품 쿠폰을 적용한다.
- 상품 쿠폰 해제: 주문 항목의 상품 쿠폰을 해제한다.
- 상품 정상가 총액 계산: 주문 항목의 상품 원 가격과 주문 수량을 곱한 총 상품 원 가격을 계산한다.
- 상품 기본 할인 총액 계산: 주문 항목의 상품 할인 금액과 주문 수량을 곱한 총 상품 할인 금액을 계산한다.
- 상품 판매가 총액: 주문 항목의 상품 판매 가격과 주문 수량을 곱한 총 상품 가격을 계산한다.
- 쿠폰 할인 금액 계산: 주문 항목에 적용된 상품 쿠폰 할인 금액을 계산한다.
- 주문 항목 최종 금액: 주문 항목의 최종 금액을 계산한다.
- 상품 가격 검증: 상품 가격 변경되었는지 검증한다.
- 상품 쿠폰 검증: 상품 쿠폰 할인 정책이 변경되었는지 검증한다.

#### 규칙

- 주문 항목을 생성할 때 상품 스냅샷이 필요하다.
- 주문 항목을 생성할 때 주문 시점의 가격 정보가 필요하다.
- 주문 항목을 생성할 때 주문 수량이 필요하다.
- 주문 항목을 생성할 때 주문 수량은 1개 이상이어야 한다.
- 쿠폰 적용은 주문서를 통해서만 적용할 수 있다.
- 상품 옵션 정보는 빈 목록일 수 있지만 `null`일 수 없다.
- 주문 항목에 쿠폰이 적용되지 않은 경우 쿠폰 할인 금액은 0원이다.
- 상품 쿠폰 할인의 기준이 되는 금액은 상품 판매가이다.
- 주문 항목의 상품 쿠폰 할인 금액을 계산할때 적용된 상품 쿠폰의 할인 금액이 상품 판매가 총액을 초과하는 경우, 실제 적용되는 쿠폰의 할인 금액은 판매가 총액을 최대 한도로 적용한다.

### 주문(Order)

사용자의 주문 데이터를 저장하는 주문 애거리거트 루트.

#### 속성

| 필드명               | 타입                | 설명         |
|-------------------|-------------------|------------|
| id                | Long              | 주문 아이디     |
| status            | OrderStatus       | 주문 상태      |
| orderName         | String            | 주문 이름      |
| orderer           | Orderer           | 주문자 정보     |
| shippingAddress   | ShippingAddress   | 배송 정보      |
| orderItems        | List<OrderItem>   | 주문 항목      |
| appliedCartCoupon | AppliedCartCoupon | 적용 장바구니 쿠폰 |
| orderAmount       | OrderAmount       | 주문 가격 정보   |
| orderCancelInfo   | OrderCancelInfo   | 주문 취소 사유   |
| createdAt         | LocalDateTime     | 주문 생성일     |

#### 행위

- create(주문 생성): 주문을 생성한다.
- paid(주문 결제): 주문을 결제 상태로 변경한다.

#### 규칙

- 주문을 생성할때 주문 필수 정보(id, status, orderName, orderer, shippingAddress, orderItems, orderAmount, createdAt)가 필요하다.
- 생성된 주문은 결제 대기(`PENDING`) 상태이다.
- 주문을 결제 상태로 변경할때 주문의 상태는 결제 대기(`PENDING`) 상태여야 한다.

주문(Order)의 주문 항목 정보를 저장하는 엔티티

#### 속성

| 필드명               | 타입                          | 설명          |

| order             | Order                       | 주문          |
| product           | ProductSnapshot             | 상품 정보       |
| productPrice      | ProductPriceSnapshot        | 상품 가격 정보    |
| appliedItemCoupon | AppliedItemCoupon           | 적용 상품 쿠폰    |
| quantity          | Integer                     | 주문 수량       |
| options           | List<ProductOptionSnapshot> | 상품 옵션       |
| orderItemAmount   | OrderItemAmount             | 주문 항목 가격 정보 |

#### 행위

- create(주문 항목 생성): 주문 항목을 생성한다.

#### 규칙

- 주문 항목을 생성할 때 상품 스냅샷이 필요하다.
- 주문 항목을 생성할 때 주문 시점의 상품 가격 정보가 필요하다.
- 주문 항목을 생성할 때 주문 수량이 필요하다.
- 주문 항목을 생성할 때 주문 수량은 1개 이상이어야 한다.
- 주문 항목을 생성할 때 상품 옵션 정보는 빈 목록일 수 있지만 `null`일 수 없다.
- 주문 항목을 생성할 때 주문 항목 가격 정보가 필요하다.

### 결제(Payment)

주문에 대한 결제 정보를 저장하는 엔티티

#### 속성

| 필드명         | 타입              | 설명       |
|-------------|-----------------|----------|
| id          | Long            | 결제 아이디   |
| orderId     | Long            | 주문 아이디   |
| userId      | Long            | 유저 아이디   |
| status      | PaymentStatus   | 결제 상태    |
| method      | PaymentMethod   | 결제 방식    |
| provider    | PaymentProvider | 결제사      |
| paymentKey  | String          | 결제 키     |
| totalAmount | Money           | 결제한 금액   |
| approvedAt  | LocalDateTime   | 결제 승인 시간 |
| failure     | PaymentFailure  | 결제 실패 사유 |

#### 행위

- create(결제 생성): 결제를 생성한다.
- approvePending(결제 승인 대기): 결제를 승인 대기 상태로 변경한다.
- approve(결제 승인): 결제를 승인한다.
- abort(결제 실패): 결제를 실패 처리한다.

#### 규칙

- 결제를 생성할 때 주문 번호가 필요하다.
- 결제를 생성할 때 유저 아이디가 필요하다.
- 결제를 생성할 때 결제 금액이 필요하다.
- 결제를 생성할 때 결제 금액이 0원이면 결제 상태는 결제 완료(`DONE`) 상태이다.
- 생성된 결제는 준비(`READY`) 상태이다.
- 결제를 승인 대기 상태로 변경할때 결제 상태는 준비(`READY`)상태여야 한다.
- 결제를 승인 대기 상태로 변경할때 승인 금액은 결제 금액과 동일해야한다.
- 결제를 승인 대기 상태로 변경할때 지원하지 않는 결제사인 경우 승인 대기로 변경할 수 없다.
- 결제를 승인 대기로 변경하면 결제 상태는 승인 대기로 변경되고 결제사와 결제 키가 초기화 된다.
- 결제를 승인할 때 결제 방식이 필요하다.
- 결제를 승인할 때 결제사가 필요하다.
- 결제를 승인할 때 결제 키가 필요하다.
- 결제를 승인할 때 결제 트랜잭션 키가 필요하다.
- 결제를 승인할 때 승인 가격이 필요하다.
- 결제를 승인할 때 승인 시간이 필요하다.
- 결제를 승인할때 결제는 승인 대기 상태여야 한다.
- 결제를 승인할때 가상 계좌 결제는 지원하지 않는다.
- 결제를 실패 처리할때 실패 사유가 필요하다.
- 결제를 실패 처리할때 결제의 상태는 준비(`READY`) 또는 승인 대기(`APPROVAL_PENDING`) 이어야 한다.

## 도메인 정책

### 1-1. 정액 할인 쿠폰 정책(FixedCouponDiscountPolicy)

정액 할인 쿠폰에 대한 정책

#### 속성

| 필드명            | 타입    | 설명    |
|----------------|-------|-------|
| discountAmount | Money | 할인 금액 |

#### 행위

- 할인 금액을 계산한다

#### 규칙

- 대상 금액의 크기와 상관없이 지정된 고정 금액이 할인 금액이다.

### 1-2. 정률 할인 쿠폰 정책(RateCouponDiscountPolicy)

정률 할인 쿠폰에 대한 정책

#### 속성

| 필드명               | 타입    | 설명           |
|-------------------|-------|--------------|
| discountRate      | int   | 할인 비율        |
| maxDiscountAmount | Money | 쿠폰의 최대 할인 금액 |

#### 행위

- 할인 금액을 계산한다.

#### 규칙

- 대상 금액에 지정된 비율을 곱하여 할인 금액이 계산된다.
- 할인 금액은 최대 할인 금액을 초과할 수 없다.
- 할인 금액이 최대 할인 금액을 초과하는 경우, 할인 금액 한도는 최대 할인 금액으로 적용된다.
- 할인 금액이 1원단위라면 10원단위로 절삭된다.
